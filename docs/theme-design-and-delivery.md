# 完整主题设计与交付规范

> 本文是 babycare 新主题的唯一执行规范，覆盖方向提案、完整方案、ImageGen 制作、图片后处理、代码接入、视觉验收与提交。
>
> 旧的“经典轻量 Hero”与“天气主题”流程已停止使用。以后新增主题默认都是一套完整视觉系统，不再只复制背景图或沿用旧主题模板。

文档版本：2026-08-27

## 1. 完整主题的定义

一套新主题必须同时包含：

- 4 张不同时段的 Hero：清晨、白天、傍晚、夜晚。
- 4 枚快捷记录图标：喂奶、排便、护理、其他。
- 6 枚今日待办图标：用药、推拿、洗澡、护理、疫苗、生长。
- 5 枚底部导航图标：今日、记录、AI、趋势、档案。
- 1 张主题列表缩略图。
- 浅色与深色两套页面配色。
- 与共享天气系统兼容的表现。
- 必要且轻量的时段动态。

基础资源共 **20 张**。只有背景或只有一组图标的方案不再作为“新主题”交付。

## 2. 不可破坏的全局规则

- 不改变信息架构、业务流程、功能名称、核心操作位置和组件尺寸。
- 中文主题名优先使用 **4 个字**；英文印章简短，只作装饰，不承载关键信息。
- 新增完整主题默认排在主题列表最上方，按“最新在前”维护；`THEMES` 必须头部插入，对应的背景和图标方案也应放在各自完整主题区域的最前面，系统默认项不受此规则影响。
- 主题可以采用完全不同的题材、材质和冷暖倾向，不需要与已有主题相似。
- 四张 Hero 必须是“同一世界、不同事件与镜头”，不能只是同一主体换光线或滤镜。
- 天气判断全主题共用。默认不重复生成晴、阴、雨等七套背景图。
- 图标必须在图片资源中校准大小和位置，不用主题专属 CSS 修正单枚图标。
- 图标颜色应能区分功能，但材质、视角、描边、光源和阴影必须成套。
- 浅色与深色模式只改变颜色、阴影和表面层级，不改变布局。
- 业务状态色和核心“记录”橙保持原语义。
- 新主题必须同时定义 `--token-brand` 和 `--token-chart-complement`，浅深各一组；两者的 hue 差需 ≥ 60°。`--brand` 绑定图表中的奶粉 + 白天，`--chart-complement` 绑定母乳 + 夜间；`--orange` 不参与图表配色，仅用于疫苗状态、日历今日、报告徽章、浮动按钮等非图表语义。
- 首页「今日待办」标题文字色与整个待办区域背景色全主题统一，新主题不得染色。
- 动态必须支持 `prefers-reduced-motion`，关闭动态后不能丢失信息。

### 「今日待办」保护边界

主题文件不得：

- 覆盖 `--token-today-plan-title`。
- 覆盖 `--token-surface-plan`。
- 为 `.today-plan` 直接设置主题背景或标题颜色。
- 用父级主题 token 间接改变上述两项的最终计算色。

浅色和深色模式都要与经典主题逐项比较最终计算色，而不只是检查变量名称。

## 3. 标准协作流程

### A. 方向提案

先提供 2～3 个差异明显的方向，每个方向说明：

- 四字主题名与一句话概念。
- 世界观和主要场景。
- 核心色彩与材质。
- 四张 Hero 的变化方式。
- 与已有主题的差异。
- 主要取舍。

必须明确推荐方向。用户选定后再写完整方案，不提前批量生图。

### B. 完整方案

使用第 4 节模板，确认以下内容：

- 四张 Hero 的主体、活动和构图是否真正不同。
- 左侧文案安全区和移动端安全主体。
- 动态落点及天气遮罩关系。
- 15 枚图标的具体语义、差异化配色和统一语言。
- 浅色与深色页面配色。
- 资源数量与实现成本。

只有完整方案确认后才进入制作。

### C. 视觉制作

推荐顺序：

1. 先制作一张代表性 Hero，验证画风、世界观、左右构图和文字可读性。
2. 连续制作另外三个时段；保持世界一致，但更换主体、事件和镜头。
3. 先制作 4 枚快捷图标，验证透明背景、材质、视角和视觉体量。
4. 按同一母提示词制作 6 枚待办和 5 枚导航图标。
5. 批量完成裁切、重心、透明边距、尺寸、色彩空间和 WebP 导出。
6. 制作浅底、深底、高对比底图标联系表及四张 Hero 联系表。
7. 从最能代表主题的一张 Hero 制作缩略图。

制作过程中保留一份临时资产清单，记录每张交付图对应的生成结果、用途和最终文件名。交付说明中至少写明使用的生图模式、提示词组概述、最终导出规格和项目保存路径，方便后续返修；临时源图和联系表默认不提交仓库。

已确认的方案只要生成结果没有明显跑题，可连续完成，不需要逐张确认。

### D. 接入与验收

按第 9 节接入代码，按第 10 节完成技术自检和最小视觉冒烟。用户负责最终视觉验收；默认不由执行方遍历所有天气、页面、模式和视口，只有涉及布局或交互、发现异常、或用户明确要求时才扩大检查范围。

### E. 提交

确认改动边界后使用单一目的的中文 Commit：

```text
功能(主题): 新增{主题名}完整主题
```

如果工作区已有用户的其他改动，必须保留并明确区分；未经要求不混入同一提交。

## 6. Hero 设计与生图规范

### 构图

- 最终比例固定为 2.5:1。
- 左侧 0%～46% 保持低细节，供白色标题、日期、天气和状态文字使用。
- 主要叙事放在右侧 52%～90%，但不能紧贴右边、顶部或底部。
- 右侧主体在手机端 `cover` 裁切后仍应可辨认。
- 不在图片中生成文字、Logo、UI、边框或水印。

### 四时段的连续性与变化

必须统一：

- 绘画媒介、材质语言和轮廓风格。
- 世界观规则、建筑或物件设计语言。
- 颗粒、景深和光影逻辑。

必须变化：

- 主体物件或主要空间。
- 角色行为或场景事件。
- 镜头角度及前中后景关系。
- 时间对应的光照和局部重点色。

### Hero 提示词骨架

```text
Use case: stylized-concept
Asset type: responsive web app Hero background, final crop 1080×432
Primary request: create the {time period} scene for the “{theme}” theme
Scene/backdrop: {scene}
Subject and activity: {unique subject and event for this period}
Style/medium: {shared style and medium}
Composition/framing: very wide 2.5:1 landscape; keep left 46% calm and low-detail for white UI copy; place the narrative focus in the right 52–90%; keep the focal point safe for mobile cover crop
Lighting/mood: {time-specific lighting}
Color palette: {palette}
Materials/textures: {shared materials}
Weather compatibility: preserve readable environmental areas for shared weather overlays
Constraints: no legible text, logo, UI, watermark or border; do not repeat another period’s subject, activity or composition
```

如果生成服务不支持 2.5:1，先生成更大的横图，再以右侧主体和左侧文字安全区为基准裁切到 1080 × 432，不能简单居中裁切。

## 7. 图标设计、透明图与后处理

### 统一语言与语义

- 图标是小尺寸功能识别物，不追求过度精细；优先清楚的轮廓和少量大色块。
- 同一主题统一材质、视角、描边、光源、阴影硬度和细节密度。
- 每枚图标使用 2～3 个主色，可加入一个独立识别色，避免全套颜色过于接近。
- 排便默认用“纸尿裤＋便便”表达，避免只画抽象符号。
- 推拿默认表达中式婴幼儿推拿，可使用手势、穴位或玉质刮痧板，避免按摩床、精油等西式 SPA 语义。
- “其他”不得因为主体结构复杂而显得更小；“记录”也没有固定缩小规则。全新生成的图标一律重新按视觉体量校准。

### 视觉体量与重心

- 先清理游离像素并裁掉透明空边，再放回 256 × 256 透明画布。
- 常规主体包围盒约占画布 70%～80%，但以视觉重量为最终判断。
- 细长、镂空、浅色主体可适当放大；宽扁、深色、实体面积大的主体适当缩小。
- 重心应在画布几何中心附近，不允许明显偏向右下、左上或贴边。
- 快捷、待办和导航三组分别做联系表；同组视觉面积差建议控制在约 10% 内。
- 必须在真实快捷区、待办卡、时间线和底部导航中再次比较。
- 若单枚图标大小或位置不合适，直接重排图片主体，不新增主题 CSS 补丁。

### 直接生成透明图

图标优先在 ImageGen 阶段直接要求真实透明背景，不把“先生成底色再抠图”作为默认流程。

```text
Use case: stylized-concept
Asset type: square app icon on a genuinely transparent background
Primary request: create one {function} icon for the “{theme}” theme
Subject: exactly {object or compact object group}
Style/medium: {shared icon style}; clean compact silhouette; low-to-medium detail; consistent {front or 3/4} viewpoint
Composition/framing: centered; optical visual mass about 72% of the square canvas; balanced transparent padding; visually align with the icon set rather than using identical geometric bounds
Lighting/mood: soft upper-left light; short contained lower-right shadow
Color palette: {2–3 function colors}
Outline: {shared outline color and weight}
Constraints: genuinely transparent background; RGBA output with real alpha; no checkerboard, solid backdrop, colored square, badge, border, text, letters, numbers, logo, watermark or photorealism; exactly the described object
```

### Alpha 校验

生成后必须检查：

1. 源文件为 RGBA 且存在真实 Alpha 通道。
2. 四角为完全透明像素。
3. 分别合成在浅色、深色和高对比色背景上，检查白边、黑边、棋盘格、游离像素和主体缺口。
4. 清理远离主体的小连通区域后，再计算包围盒和视觉重心。
5. 导出 WebP 后重新检查 Alpha 和 256px 下的辨识度。

本地处理适合做无损裁切、连通区域清理、缩放、重心和平衡校准；不适合用宽松亮度阈值强行抠白底。珍珠白、高光、柔影和浅色描边会被阈值误删，形成破损。

透明失败时依次处理：

1. 用原图重新要求服务保留主体并输出真实 Alpha。
2. 仍失败时，重新生成不与主体颜色重叠的单一高饱和背景，再本地色键转 Alpha。
3. 任何兜底处理都要重新执行三种背景检查，不得直接入库。

## 8. 天气与动态

共享天气状态为：晴、多云、阴、雨、雾、雪、雷雨。

新主题默认只调整：

- 天气层透明度、混合模式和遮挡关系。
- 粒子方向、密度或形态，使其符合主题空间语义。
- 阴雨状态下的明度与饱和度，避免主题被统一染成冷灰。

例如海底主题不能直接表现从天空落下的雨线，可把雨语义转为上浮气泡、水流和环境扰动，但仍需保留“当前是雨天”的可辨识反馈。

只有共享系统无法表达关键语义时才新增天气图片；这属于范围扩大，需要重新确认。

时段装饰动态规则：

- 每个时段最多 2～3 个动态点。
- 周期建议 5～10 秒，位移 2～6px，光照透明度变化 8%～15%。
- 只做局部光斑、蒸汽、薄雾、微粒、灯光呼吸等环境运动。
- 不快速闪烁、不大幅缩放、不持续弹跳、不让整张画面漂浮。
- 动态不能盖过天气反馈。
- `prefers-reduced-motion` 下停止动画，并保留完整静态画面。
