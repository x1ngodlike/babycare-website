# 宝宝照护记录 UI/UX 规范

## 设计原则

- 优先保证快速记录、清晰反馈和低认知负担。
- 复用同一类组件，不因页面不同重复设计按钮、菜单或弹窗。
- 插画只服务于品牌与空状态，不进入高信息密度列表、图表和设置项。
- 所有交互同时支持触摸、键盘与读屏语义，并尽量符合 WCAG 2.2 AA。

## 设计变量

- 间距：4、8、12、16、24、32px。
- 点击区域：不小于 44 × 44px；常规表单高度 48px。
- 圆角：控件 10px，卡片 16px，弹窗 20px，标签使用胶囊圆角。
- 页面标题：桌面 32px、移动端 28px；分区标题 20px；卡片标题 16px；正文 14px；标签 13px；辅助文字 12px。
- 阴影仅用于弹窗、操作菜单和悬浮反馈，不用于普通内容卡片。

## 颜色语义

- 页面背景 `--surface-page`，内容背景 `--surface-card`，弱背景 `--surface-subtle`。
- 主文字 `--ink`，辅助文字 `--text-secondary`，更弱文字仅用于非关键短标签。
- 绿色表示主操作、已完成与正常状态；橙色表示提醒；红色只表示危险操作或错误。
- 普通正文和辅助文字必须达到 4.5:1；图标与控件边界至少达到 3:1。

## 组件规则

- `SegmentedControl`：用于互斥视图，支持左右方向键，选中项只有一个。
- `ActionMenu`：所有“…”操作统一为 44px 触发区、128px 菜单和 13px 文案。
- `Dialog`：锁定焦点、Escape 关闭、关闭后恢复焦点；有未保存内容时必须确认。
- `ConfirmDialog`：标题说明结果，正文说明影响，危险确认按钮使用红色。
- `Switch`：必须有明确的可读名称；保存中禁用并提供反馈。
- `EmptyState`：标题说明当前状态，正文说明下一步，可选一个主要操作。
- `Toast`：成功与失败都必须可读；可撤销操作应提供明确的“撤销”。

## 响应式

- 320–520px：单列，卡片内边距 12–16px。
- 521–759px：单列或紧凑双列。
- 760–1079px：主要内容可双列，禁止产生无意义的大面积空白。
- 1080px 以上：页面最大宽度 1080px，不继续拉伸正文。

## 插画

- 暖米白、鼠尾草绿和柔和橙色，轻拟物、圆润、低饱和、透明背景、无文字。
- 空状态使用 1:1；登录主视觉使用 4:3。
- 同组素材保持相同光源、视角、描边与阴影强度。
- 首批场景：无记录、无搜索结果、无接种安排、登录家庭照护。
