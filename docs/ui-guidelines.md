# 宝宝照护记录：UI/UX 规范

> 本文规定当前产品的界面与交互原则。文档导航见 [README.md](./README.md)，功能规则见 [product.md](./product.md)，实现细节见 [technical.md](./technical.md)。

## 1. 设计原则

- 任务优先：先呈现今天需要知道和完成的事情，再提供趋势与管理能力。
- 简洁克制：避免无意义渐变、装饰卡片、过度圆角和阴影堆叠。
- 一致复用：相同操作使用相同按钮、菜单、弹窗和状态语言。
- 移动优先：常用操作适合单手触控，同时保证桌面端信息密度。
- 明确反馈：保存、失败、离线、加载、空状态和危险操作都有清晰反馈。
- 可访问：尽量符合 WCAG 2.2 AA，支持键盘、焦点、读屏和减少动效偏好。

## 2. 设计系统

### 2.1 色彩

以 `src/styles/base.css` 中的 CSS 变量为唯一实现来源：

- 页面：`--surface-page`。
- 卡片：`--surface-card`。
- 弱背景：`--surface-subtle`、`--surface-muted`。
- 主文字：`--ink`。
- 辅助文字：`--text-secondary`、`--muted`。
- 主操作与正常状态：`--green`、`--green-deep`。
- 温和提示：橙色系。
- 错误和危险操作：`--danger`。

正文对比度应达到 4.5:1，非文字控件和焦点边界至少达到 3:1。颜色不能是唯一的状态表达方式。

### 2.2 字体与层级

使用系统中文字体栈，不依赖外部字体服务。

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| 页面主标题 | 28–32px | 页面或关键问候 |
| 分区标题 | 20px | 页面内一级分区 |
| 卡片标题 | 16px | 独立功能卡片 |
| 正文 | 14px | 表单、列表主要信息 |
| 标签 | 13px | 状态和紧凑说明 |
| 辅助文字 | 12px | 时间、来源、补充说明 |

移动端承载业务含义的文字不小于 12px；11px 只允许用于非关键、空间受限且有其他方式可识别的信息。主信息允许 700–800 字重；正文避免大面积粗体。中英文和数字之间保持自然空隙，日期、时间和单位写法保持一致。

### 2.3 间距与尺寸

- 基础间距：4、8、12、16、24、32px。
- 最小触控区：44 × 44px。
- 常规输入控件：最小高度 48px。
- 控件圆角约 10px，卡片约 16px，弹窗约 20px。
- 卡片只使用统一的轻量阴影变量；弹窗、操作菜单、Toast 和悬浮层可使用更明确的层级阴影，禁止叠加装饰性阴影。

## 3. 页面结构

### 3.1 今日页

信息顺序：

1. Hero：日期、问候、宝宝精确月龄、最近状态和头像。
2. 今日指标：母乳、奶粉、喂奶次数、排便次数。
3. 快捷记录：喂奶、排便、用药、其他。
4. 今日计划：逾期疫苗、定时任务、无时间任务、本周成长记录。
5. 信息摘要：疫苗安排、昨日报告。
6. 今日时间线。

Hero 文案规范：

- 问候：`{时间段问候}，{昵称或姓名}{当前身份称谓}～`。
- 时间段：05:00–10:59"早上好"，11:00–13:59"中午好"，14:00–17:59"下午好"，18:00–22:59"晚上好"，23:00–04:59"夜深了"。
- 年龄：`{姓名} · 2个月3天`；满一岁后为 `1岁2个月3天`，不使用"满月宝宝"等阶段标签。
- 状态：Hero 摘要行使用 `上次记录：{HH:MM} · {记录摘要}`（如 `上次记录：03:02 · 益生菌`）。预计喂奶与喂奶间隔预测由独立的预测横幅（PredictionBanner）展示，基于近 7 天喂奶间隔；预测不可用时横幅不展示或给出提示。
- 年龄和状态在移动端保持单行，空间不足时尾部省略；完整状态写入 `title` 和无障碍名称。
- 问候语使用系统字体，不加载额外中文字体文件。

“今日计划”是计划提醒的唯一页面内入口，不再通过定时 Toast 重复提醒。

### 3.2 记录页

- 无搜索时按选中日期显示时间线。
- 搜索时结果时间必须同时包含月日和时分，避免跨日记录混淆。
- 类型和录入人筛选与搜索可组合。
- 删除入口仅对管理身份显示；危险操作必须二次确认。
- 时间线点击记录图标弹出的详情窗口中，在"备注"之上展示"补充说明（subject）"字段，用于显示 type=note 的标题或其他类型的结构化补充主题。

### 3.3 趋势页

- 图表先展示单位、时间范围和汇总，再展示细节。
- 不用颜色单独区分数据系列；图例和文本必须明确。
- 空数据时解释如何产生数据，而不是显示空图表。
- **近 3 日喂奶节奏图**：
  - 数据窗口为"今天 + 前 2 天"共 3 天的喂奶间隔点。
  - x 轴每个点标注月/日 + 时间。
  - 虚线为近 3 日平均间隔，右上角标注 `平均 X.Xh`。
  - 纵轴动态裁剪下方空白，最小跨度 2h 避免过度放大。
- 周/月统计：以 7 天桶（周模式）或整月桶（全部模式）聚合每日平均间隔。

### 3.4 档案页

- 宝宝资料、成长记录和疫苗记录分区清晰。
- 成长数据同时显示测量日期、精确月龄和录入人。
- 疫苗的“已接种”和“接下来”严格分开；已完成项目不能作为下一针显示。
- 疫苗摘要的“查看记录”使用右上角轻量文字按钮；“已接种 N 针”与“待接种”放在同一信息句中，避免重复占用标题区域。

### 3.5 设置页

- 入口按照护、家庭、系统分组，但避免多余可见标题。
- 管理能力随角色隐藏，不只依赖禁用状态。
- Token、API Key 等密钥默认遮挡，留空表示不修改。
- 设置保存后给出就地状态反馈。
- **备份与恢复列表 UI**：
  - 每行以"时间 + 手动/自动类型标签 + 文件大小"为主要信息。
  - 选中圆圈在最左侧，单选指示清晰。
  - 删除按钮在右侧（距右边界 10px），悬停显示 ×，危险操作需二次确认。
  - 4 个操作按钮（立即备份、从服务器恢复、下载备份文件、导入备份文件）字号统一 14px。
- **导入方式选择对话框**：
  - 标题"导入备份文件"，副标题"选择导入方式"。
  - 默认选中"增量合并"（保留现有数据，合并备份中的记录）；"全量替换"为危险选项（选中时确认按钮变红，文案强调"清除当前所有数据，完整恢复备份内容"）。
  - 单选按钮视觉为 ● 选中 / ○ 未选中。

## 4. 通用组件

### 4.1 按钮

- 主按钮：页面或弹窗中最重要的单一动作。
- 次按钮：取消、返回、预约和辅助动作。
- 危险按钮：删除、停用等不可轻易恢复的动作。
- 主按钮文案统一为「动词 + 对象」，如“保存记录”“保存资料”“保存预约”“标记达成”，不用“确认保存”“确定”。
- 忙碌态统一为「对象 + 中 + …」：如“保存中…”“备份中…”“导出中…”“登录中…”。
- 加载时禁用重复提交并将文案改为忙碌态。

### 4.2 ActionMenu

- 触发区至少 44 × 44px，使用可读名称描述对应对象。
- 菜单宽度约 128px，每项高度至少 44px。
- 危险项使用红色并置于末尾。

### 4.3 SegmentedControl / ChoiceField / Switch 分工

三种选择控件职责不同，不得混用：

- **SegmentedControl**：页面/弹窗内的视图或模式切换（如“照护记录 / 疫苗记录”、日期视图“七日 / 按天”）。选中即生效，不参与表单提交语义。
- **ChoiceField**：表单内的单选枚举（如“宝宝性别”“排便量”），跟随表单一起保存。
- **Switch**：独立的即时开/关状态（如推送规则开关），切换立即生效并反馈。

### 4.4 Switch

- 必须有可读标签，不能只显示开关本体。
- 仅用于立即表达开/关状态；若仍需点击保存，页面应明确说明。
- 保存中禁用并反馈结果。

### 4.5 Dialog 与底部 Sheet

- 打开时移动焦点到弹窗，Tab 不离开弹窗，Escape 可关闭。
- 关闭后恢复到触发控件。
- 有未保存内容时关闭需确认。
- 手机端可贴底显示，桌面端居中。
- 弹窗骨架统一使用 `Modal` 组件（遮罩、标题栏、焦点圈定、Escape/遮罩关闭）；有未保存内容的表单使用 `useDirtyClose` 统一确认关闭。

### 4.6 Feedback 顶栏提示

- 位置：屏幕顶部固定（`position: fixed`，避开 iOS 安全区），水平居中。
- 形状：胶囊形（999px 圆角），带轻微阴影。
- 配色：成功 = 浅绿底 + 深绿文字边框；错误 = 浅红底 + 深红文字边框。
- 动画：
  - 进入：`feedback-in` 从上方 18px 处渐入落下（320ms）。
  - 退出：淡出 + 上移 12px（220ms）。
- 行为：
  - 成功提示 4 秒后自动消失。
  - 错误提示必须用户点击"×"关闭按钮才消失。
  - 关闭按钮圆形，24×24px，悬停显示实心背景。
- 用途：保存结果、错误、离线暂存、同步完成、备份导入完成等。
- 不用于重复展示今日计划或定时提醒。
- 错误提示必须说明问题和下一步；成功提示简洁如"备份文件已下载"。

### 4.6.1 全局 Toast 与内嵌 Feedback 分工

- **全局 Toast**（`.toast`）：用于弹窗内编辑后、或跨页面的操作结果（如"记录已保存""预约已取消"），顶部固定胶囊、自动消失、可带撤销动作。App 主容器统一渲染。
- **内嵌 Feedback**（`.success-text` / `.error-text`）：用于设置卡片等页面内的就地反馈，紧贴操作区，不自动消失的常驻状态。
- 规则：操作发生在弹窗内或跨页 → 用 Toast；操作在页面卡片内 → 用内嵌 Feedback。同一操作不得两套提示并用。

### 4.7 EmptyState

- 标题描述现状，正文解释下一步。
- 最多提供一个主要操作。
- 插画只用于空状态和品牌场景，不进入高密度列表。
- 数据为空场景必须配插画（`/illustrations/*.webp`）；纯引导场景（如 AI 对话首页）可豁免，使用圆点占位 + 主操作。

## 5. 表单与状态

所有可编辑功能应考虑：

- 默认、悬停、按下、聚焦、选中和禁用。
- 加载、空状态、错误、成功和离线。
- 必填、格式错误、范围错误和业务冲突。
- 权限不足时隐藏管理入口；直接访问接口仍由服务端拒绝。

日期与时间使用自研选择器：

- 日期按钮保留 44px 触控目标；极小屏可压缩视觉高度但不能影响可操作性。
- 今天、选中、禁用和范围外日期必须清晰区分。
- 时间按 24 小时制显示为 `HH:MM`。

## 6. 疫苗界面规范

- 预约日期优先显示；有系统建议时可在次级文案中同时说明。
- 今日、未来 7 天和逾期状态使用文字，不只靠颜色。
- “已预约”“待预约”“逾期 N 天”“已接种”术语保持一致。
- 免疫规划和自费疫苗使用类型标签，但不把类型颜色当作唯一信息。
- 安全提示固定说明“具体接种与补种安排请以接种门诊为准”。
- 已设置门诊预约的项目在操作菜单中显示“添加到手机日历”；浏览器端使用“下载日历日程”。

## 7. 消息推送界面规范

- 明确通道为 PushPlus 微信，不写“浏览器推送”。
- 顶部显示未配置、已关闭或已开启。
- 总开关与早报、喂奶间隔、用药照护子开关分层展示。
- 喂奶一级阈值至少 30 分钟，二级必须大于一级。
- 每种推送提供独立测试按钮，结果在设置卡片内反馈。
- PushPlus 消息使用系统字体、HTML 卡片、可读标题和状态标签。
- Android 的“APP 通知”与 PushPlus 分开展示，提供总开关及早报、喂奶、照护、疫苗分类开关；每类测试按钮仅超级管理员可见。

## 8. 头像与图片

- 首页头像：76 × 76px；≤400px 时 64 × 64px。
- 档案头像按布局使用 48–56px。
- 裁剪输出：512 × 512px WebP。
- 裁剪支持单指拖动和双指缩放，手势期间禁止页面滚动；底部操作与说明必须避开安全区且不能被图片或按钮遮挡。
- 缩放范围和初始位置应确保裁剪区域始终被图片覆盖；处理失败时保留原资料并给出错误。
- 无头像显示默认小熊插画。
- 存储路径：`{DATA_DIR}/uploads/avatars/avatar_{uuid}.webp`；访问路径：`/avatars/{filename}`。

## 9. 响应式与无障碍

主要断点：

- 320–520px：单列，底部导航，卡片内边距 12–16px。
- 521–759px：单列或局部紧凑双列。
- 760–1079px：主要内容可双列。
- ≥1080px：内容最大宽度 1080px，不无限拉伸。

通用要求：

- `:focus-visible` 焦点清晰且不被裁切。
- 图标按钮提供 `aria-label`，装饰图片使用空 `alt`。
- 弹窗设置 `role="dialog"`、`aria-modal` 和标题关联。
- 动态结果使用适当的 `role="status"` 或 `role="alert"`。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
