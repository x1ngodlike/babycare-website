# 宝宝照护记录：UI/UX 规范

> 本文规定当前产品的界面与交互原则。文档导航见 [README.md](./README.md)，功能规则见 [product.md](./product.md)，实现细节见 [technical.md](./technical.md)。
> HTML 配色与组件预览见 [current-ui-system.html](./current-ui-system.html)。当前基线更新于 2026-08-21。

## 当前实现基线（2026-08）

当前界面采用 **TDesign 交互逻辑 × BabyCare 暖系品牌视觉**：保留现有页面结构、功能流程、照护插画和橙色核心记录动作；按钮、表单、选择、反馈、浮层、图标和主题由共享 token 与组件状态统一控制。

- CSS 加载顺序固定为 `foundations.css → base/layout/page styles → ui.css → components.css`。`foundations.css` 只放全局 token；`components.css` 只放跨页面组件状态和迁移期覆盖；页面文件不得重新定义全局 token。
- 功能图标统一使用项目现有 `lucide-react`，默认线宽 `1.8`，尺寸使用 16/20/24px；照护类型、家庭身份和品牌插画继续使用现有图片资源，不用线性图标替代。
- 底部五项导航使用项目自有 PNG 图标，统一 `38 × 38px`；导航文字统一 `12px / 700 / 15px`，图文间距 `3px`，选中态不缩放、不位移。
- 橙色只用于核心记录与首要 CTA，浅色、深色主题均使用白色文字和图标；不得在页面内创建另一套橙色。
- 分段选择、单选按钮、开关统一提供默认、悬停、按下、聚焦、选中和禁用状态；选中状态同时使用边框、底色和文字，不只依靠颜色。
- Toast 与全局成功/失败反馈位于统一反馈层；表单错误保持就地展示。成功信息使用 `role="status"`，错误使用 `role="alert"`，可关闭反馈必须提供可读名称。
- 浮层使用 `--layer-*` 语义层级：固定状态 20、导航 25、悬浮动作 30、Toast 100、遮罩 200、对话框/菜单 210–220、关键确认 300。新代码不得直接添加大于等于 20 的裸 `z-index`。
- 中文数字与单位格式统一为 `120 mL`、`62.5 cm`、`6.35 kg`、`08:30`；范围使用短横线 `–`，单位大小写不可混用。
- `npm run check:css` 会检查 CSS 语法、未定义 token、`!important` 迁移预算，并报告仍待语义化的高层级裸值。

## 1. 设计原则

- 任务优先：先呈现今天需要知道和完成的事情，再提供趋势与管理能力。
- 简洁克制：避免无意义渐变、装饰卡片、过度圆角和阴影堆叠。
- 一致复用：相同操作使用相同按钮、菜单、弹窗和状态语言。
- 移动优先：常用操作适合单手触控，同时保证桌面端信息密度。
- 明确反馈：保存、失败、离线、加载、空状态和危险操作都有清晰反馈。
- 可访问：尽量符合 WCAG 2.2 AA，支持键盘、焦点、读屏和减少动效偏好。

## 2. 设计系统

### 2.1 视觉方向

整体气质为“温暖、自然、可靠、轻童趣”。界面首先服务于夜间、单手、多人交接等真实照护场景，插画和品牌色用于建立亲和感，不能削弱信息读取和操作效率。

- 绿色表达品牌、正常状态和主要行动；橙色只强调最重要的记录动作和温和提醒。
- 大面积背景保持低饱和，正文和数据使用稳定的中性色，不使用彩色正文制造层级。
- 插画集中在 Hero、空状态和记录类型图标，高密度列表不增加装饰图片。
- 渐变只用于 Hero 背景和全局核心记录动作；普通按钮、卡片、输入框使用纯色。
- 胶囊形只用于状态标签、身份状态和短筛选项，普通卡片与按钮不得统一做成胶囊。
- 普通卡片依靠背景、边框和间距分组；只有导航、弹窗、菜单和悬浮层使用阴影。

### 2.2 Token 分层与命名

视觉变量按三层组织，禁止页面直接创造第四套局部色板：

1. **基础值（primitive）**：原始色值、字号和尺寸，只在 Token 文件内部使用。
2. **语义值（semantic）**：按用途命名，是组件默认使用的变量。
3. **组件值（component）**：仅在组件确实需要稳定特例时，从语义值派生。

示例：

```css
/* 基础值不应出现在页面选择器中 */
--palette-green-600: #526d59;

/* 浅色和深色主题映射语义角色 */
--color-action-primary: var(--palette-green-600);
--color-text-primary: var(--palette-neutral-900);

/* 组件通常直接使用语义值 */
.btn.primary { background: var(--color-action-primary); }
```

现阶段允许保留既有变量名，迁移完成前不要一次性删除；新规则优先使用下表中的目标命名。

### 图表双色绑定规则

图表使用两组颜色，每组绑定固定的**数据语义**，与主题无关：

| CSS 变量 | Token | 绑定的指标 | 配色要求 |
|---|---|---|---|
| `--brand` | `token-brand` | **奶粉 + 白天** | 每个主题定义自己的品牌主色 |
| `--chart-complement` | `token-chart-complement` | **母乳 + 夜间** | 必须与 brand 保持足够色相和明度差，不与主色混淆 |

`--orange` 保留给非图表语义（疫苗状态、日历今日、报告徽章、浮动按钮等），与图表配色解耦。

正文对比度达到 4.5:1；大号文字、非文字控件、选中边界和焦点边界至少达到 3:1。深色模式只重新映射语义变量，原则上不为每个页面重复整套选择器。

### 2.4 字体与层级

使用系统中文字体栈，不依赖外部字体服务。

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---:|---:|---|
| `--text-display` | 28–32px / 1.2 | 800 | 首页问候和极少数品牌场景 |
| `--text-page-title` | 24px / 1.3 | 800 | 历史、趋势、档案等页面标题 |
| `--text-section-title` | 20px / 1.4 | 700–800 | 页面一级分区 |
| `--text-card-title` | 16px / 1.45 | 700 | 卡片和弹窗内标题 |
| `--text-body` | 14px / 1.6 | 400–600 | 正文、表单、列表主要信息 |
| `--text-label` | 13px / 1.45 | 600–700 | 按钮、筛选、状态标签 |
| `--text-meta` | 12px / 1.5 | 400–600 | 时间、来源、补充说明 |

移动端承载业务含义的文字不小于 12px；11px 只允许用于非关键、空间受限且有其他方式可识别的信息，9–10px 不承载日期、时间、单位或操作含义。主信息允许 700–800 字重；正文避免大面积粗体。数字和单位不得依靠字号过小制造层级，例如使用 `120 mL`，单位最小 12px。

系统字体栈统一为：`Inter, ui-rounded, "SF Pro Rounded", "PingFang SC", "Microsoft YaHei", sans-serif`。数字密集区域可使用 `font-variant-numeric: tabular-nums`，方便时间和指标纵向对齐。

### 2.5 间距、尺寸与密度

- 间距序列固定为 4、8、12、16、24、32、40px；优先使用 `--space-1/2/3/4/6/8/10`。
- 页面水平边距：移动端 12–16px，平板 20–24px，桌面内容区 24–32px。
- 卡片内边距：紧凑卡片 12px，常规卡片 16px，设置或复杂表单 20–24px。
- 相邻操作间距至少 8px；危险操作与普通操作之间至少 12px，或使用明确分组。
- WCAG 2.2 AA 的目标区域基线为 24 × 24 CSS px，并满足相邻目标间距；本产品的核心和高频触控操作使用 44 × 44px 以上热区。
- 主按钮、保存、删除、今日待办、底部导航和记录入口：最小热区 44px。
- 普通筛选和低频工具按钮：视觉高度可为 36–40px，但相邻目标不得拥挤；纯图标视觉可为 24–32px，外层热区仍建议 44px。
- 常规控件视觉高度为 40px，大型或高频操作使用 44px；触控热区与视觉高度分开管理，不要求所有按钮都做成 44px 高。

### 2.6 圆角、边框与阴影

| Token | 建议值 | 用途 |
|---|---:|---|
| `--radius-small` | 4px | 极小内部元素 |
| `--radius-control` | 8px | 按钮、输入框、选择器 |
| `--radius-inner` | 12px | 卡片内分组、列表容器 |
| `--radius-card` | 16px | 普通卡片和分组 |
| `--radius-dialog` | 20px | 弹窗和移动端 Sheet |
| `--radius-pill` | 999px | 状态、身份和短筛选标签 |

- 1px 默认边框用于卡片和输入框；选中或聚焦不能仅改变阴影，必须有明确边框或焦点环。
- `--shadow-card` 默认应为 `none` 或极弱阴影；普通列表行不使用阴影。
- `--shadow-popover` 用于 ActionMenu、日期选择器和 Toast。
- `--shadow-dialog` 用于 Modal 和 Sheet。
- `--shadow-navigation` 只用于固定导航，不能与卡片阴影叠加。

浅色主题不得重新扩大整套圆角；浅色、深色只改变颜色和阴影明暗，不改变组件几何尺寸。

### 2.7 栅格、断点与层级

- `320–520px`：单列，底部导航，页面边距 12–16px。
- `521–759px`：单列或局部紧凑双列，页面边距 16–20px。
- `760–1079px`：主要内容允许双列，保留触控友好尺寸。
- `≥1080px`：内容最大宽度 1080px，底部导航限制宽度并居中，不无限拉伸。

页面栅格优先使用 12 列思维，但实现可采用 CSS Grid 的两列布局；组件不依赖固定页面宽度。统一层级建议为：页面内容 `0`、固定顶部状态 `20`、底部/桌面导航 `30`、Toast `100`、遮罩 `200`、弹窗 `210`、操作菜单 `220`。除必要的局部堆叠外，不新增任意 z-index。

## 3. 页面结构

### 3.1 今日页

信息顺序：

1. Hero：日期、问候、宝宝精确月龄、最近状态和头像。
2. 今日指标：母乳、奶粉、喂奶次数、排便次数。
3. 快捷记录：喂奶、排便、用药、其他。
4. 今日计划：逾期疫苗、定时任务、无时间任务、本周成长记录。
5. 信息摘要：疫苗安排、昨日报告。
6. 今日时间线。

Hero 文案规范：

- 问候：`{时间段问候}，{昵称或姓名}{当前身份称谓}～`。
- 时间段：05:00–10:59"早上好"，11:00–13:59"中午好"，14:00–17:59"下午好"，18:00–22:59"晚上好"，23:00–04:59"夜深了"。
- 年龄：`{姓名} · 2个月3天`；满一岁后为 `1岁2个月3天`，不使用"满月宝宝"等阶段标签。
- 状态：Hero 摘要行使用 `上次记录：{HH:MM} · {记录摘要}`（如 `上次记录：03:02 · 益生菌`）。预计喂奶与喂奶间隔预测由独立的预测横幅（PredictionBanner）展示，基于近 7 天喂奶间隔；预测不可用时横幅不展示或给出提示。
- 年龄和状态在移动端保持单行，空间不足时尾部省略；完整状态写入 `title` 和无障碍名称。
- 问候语使用系统字体，不加载额外中文字体文件。

“今日计划”是计划提醒的唯一页面内入口，不再通过定时 Toast 重复提醒。

### 3.2 记录页

- 无搜索时按选中日期显示时间线。
- 搜索时结果时间必须同时包含月日和时分，避免跨日记录混淆。
- 类型和录入人筛选与搜索可组合。
- 删除入口仅对管理身份显示；危险操作必须二次确认。
- 时间线点击记录图标弹出的详情窗口中，在"备注"之上展示"补充说明（subject）"字段，用于显示 type=note 的标题或其他类型的结构化补充主题。

### 3.3 趋势页

- 图表先展示单位、时间范围和汇总，再展示细节。
- 不用颜色单独区分数据系列；图例和文本必须明确。
- 空数据时解释如何产生数据，而不是显示空图表。
- **近 3 日喂奶节奏图**：
  - 数据窗口为"今天 + 前 2 天"共 3 天的喂奶间隔点。
  - x 轴每个点标注月/日 + 时间。
  - 虚线为近 3 日平均间隔，右上角标注 `平均 X.Xh`。
  - 纵轴动态裁剪下方空白，最小跨度 2h 避免过度放大。
- 周/月统计：以 7 天桶（周模式）或整月桶（全部模式）聚合每日平均间隔。

### 3.4 档案页

- 宝宝资料、成长记录和疫苗记录分区清晰。
- 成长数据同时显示测量日期、精确月龄和录入人。
- 疫苗的“已接种”和“接下来”严格分开；已完成项目不能作为下一针显示。
- 疫苗摘要的“查看记录”使用右上角轻量文字按钮；“已接种 N 针”与“待接种”放在同一信息句中，避免重复占用标题区域。

### 3.5 设置页

- 入口按照护、家庭、系统分组，但避免多余可见标题。
- 管理能力随角色隐藏，不只依赖禁用状态。
- Token、API Key 等密钥默认遮挡，留空表示不修改。
- 设置保存后给出就地状态反馈。
- **备份与恢复列表 UI**：
  - 每行以"时间 + 手动/自动类型标签 + 文件大小"为主要信息。
  - 选中圆圈在最左侧，单选指示清晰。
  - 删除按钮在右侧（距右边界 10px），悬停显示 ×，危险操作需二次确认。
  - 4 个操作按钮（立即备份、从服务器恢复、下载备份文件、导入备份文件）字号统一 14px。
- **导入方式选择对话框**：
  - 标题"导入备份文件"，副标题"选择导入方式"。
  - 默认选中"增量合并"（保留现有数据，合并备份中的记录）；"全量替换"为危险选项（选中时确认按钮变红，文案强调"清除当前所有数据，完整恢复备份内容"）。
  - 单选按钮视觉为 ● 选中 / ○ 未选中。

## 4. 通用组件

### 4.1 按钮

- 主按钮：页面或弹窗中最重要的单一动作。
- 次按钮：取消、返回、预约和辅助动作。
- 危险按钮：删除、停用等不可轻易恢复的动作。
- 文字按钮：页面内低权重跳转或展开，不承担保存和删除。
- 图标按钮：关闭、更多、刷新等已被用户熟悉的操作，必须提供 `aria-label`。
- 同一操作区最多一个主按钮；危险按钮不能与主按钮使用相同颜色和层级。
- 移动端常规按钮最小高度 44px，表单主按钮建议 48px；桌面紧凑工具栏允许 36–40px。
- 按钮水平内边距：紧凑 12px、常规 16px、强调 20px；图标与文案间距 8px。
- 默认使用 `--radius-control`；只有短标签式切换器或明确的悬浮主操作允许使用胶囊形。
- 主按钮文案统一为「动词 + 对象」，如“保存记录”“保存资料”“保存预约”“标记达成”，不用“确认保存”“确定”。
- 忙碌态统一为「对象 + 中 + …」：如“保存中…”“备份中…”“导出中…”“登录中…”。
- 加载时禁用重复提交并将文案改为忙碌态。
- 悬停只增强边框或背景，不依赖位移动画；按下可使用不超过 `.98` 的轻微缩放。
- 聚焦必须显示统一焦点环；禁用态同时降低颜色对比和移除点击反馈，但文案仍需可读。

### 4.2 ActionMenu

- 触发区至少 44 × 44px，使用可读名称描述对应对象。
- 菜单宽度约 128px，每项高度至少 44px。
- 危险项使用红色并置于末尾。

### 4.3 SegmentedControl / ChoiceField / Switch 分工

三种选择控件职责不同，不得混用：

- **SegmentedControl**：页面/弹窗内的视图或模式切换（如“照护记录 / 疫苗记录”、日期视图“七日 / 按天”）。选中即生效，不参与表单提交语义。
- **ChoiceField**：表单内的单选枚举（如“宝宝性别”“排便量”），跟随表单一起保存。
- **Switch**：独立的即时开/关状态（如推送规则开关），切换立即生效并反馈。

### 4.4 Switch

- 必须有可读标签，不能只显示开关本体。
- 仅用于立即表达开/关状态；若仍需点击保存，页面应明确说明。
- 保存中禁用并反馈结果。

### 4.5 Dialog 与底部 Sheet

- 打开时移动焦点到弹窗，Tab 不离开弹窗，Escape 可关闭。
- 关闭后恢复到触发控件。
- 有未保存内容时关闭需确认。
- 手机端可贴底显示，桌面端居中。
- 弹窗骨架统一使用 `Modal` 组件（遮罩、标题栏、焦点圈定、Escape/遮罩关闭）；有未保存内容的表单使用 `useDirtyClose` 统一确认关闭。

### 4.6 Feedback 顶栏提示

- 位置：屏幕顶部固定（`position: fixed`，避开 iOS 安全区），水平居中。
- 形状：胶囊形（999px 圆角），带轻微阴影。
- 配色：成功 = 浅绿底 + 深绿文字边框；错误 = 浅红底 + 深红文字边框。
- 动画：
  - 进入：`feedback-in` 从上方 18px 处渐入落下（320ms）。
  - 退出：淡出 + 上移 12px（220ms）。
- 行为：
  - 成功提示 4 秒后自动消失。
  - 错误提示必须用户点击"×"关闭按钮才消失。
  - 关闭按钮圆形，24×24px，悬停显示实心背景。
- 用途：保存结果、错误、离线暂存、同步完成、备份导入完成等。
- 不用于重复展示今日计划或定时提醒。
- 错误提示必须说明问题和下一步；成功提示简洁如"备份文件已下载"。

### 4.6.1 全局 Toast 与内嵌 Feedback 分工

- **全局 Toast**（`.toast`）：用于弹窗内编辑后、或跨页面的操作结果（如"记录已保存""预约已取消"），顶部固定胶囊、自动消失、可带撤销动作。App 主容器统一渲染。
- **内嵌 Feedback**（`.success-text` / `.error-text`）：用于设置卡片等页面内的就地反馈，紧贴操作区，不自动消失的常驻状态。
- 规则：操作发生在弹窗内或跨页 → 用 Toast；操作在页面卡片内 → 用内嵌 Feedback。同一操作不得两套提示并用。

### 4.7 EmptyState

- 标题描述现状，正文解释下一步。
- 最多提供一个主要操作。
- 插画只用于空状态和品牌场景，不进入高密度列表。
- 数据为空场景必须配插画（`/images/illustrations/*.webp`）；纯引导场景（如 AI 对话首页）可豁免，使用圆点占位 + 主操作。

### 4.8 表单控件

- 输入框、选择器和日期时间触发器使用相同高度、圆角、边框和焦点环。
- 浅色默认背景为纯白 `#ffffff`；深色默认背景为控件表面 `#303932`，不得直接复用深色卡片背景。
- 输入框、文本域、下拉框、日期时间触发器、快捷时间、分段单选和护理项目选择统一使用 `8px` 圆角。
- 选中态使用品牌绿边框、浅绿表面和深绿文字；禁用、只读状态使用弱化表面，不能与默认状态混淆。
- 标签位于控件上方，标签与控件间距 6–8px；必填信息通过文字或 `required` 语义表达，不只显示红色星号。
- 占位符只提供示例，不能替代标签；帮助文字位于控件下方并说明格式或影响。
- 校验优先在失焦或提交后出现；错误文案必须同时说明问题和修复方法。
- 禁用表示用户当前不能操作；只读表示内容可复制但不能修改，两者视觉和语义不得混用。
- 一组表单控件纵向间距 16px；逻辑分组之间使用 24px 或 `fieldset`。

### 4.9 Card 与 List Row

- Card 用于形成独立信息分组，不用于包裹每一行内容。连续同类记录使用列表和分隔线。
- 普通卡片使用 `--color-surface-card`、1px 默认边框、`--radius-card`，默认无阴影。
- 卡片标题区只保留标题、必要状态和最多一个主要操作；更多操作进入 ActionMenu。
- List Row 的主信息、次信息和尾部操作顺序固定；移动端不能因尾部按钮挤压主信息到不可读。
- 整行可点击时使用单一交互元素，不在可点击行内嵌另一个无关按钮；确需独立操作时明确拆分区域和无障碍名称。
- 加载状态保持卡片或列表原有尺寸，避免内容出现后发生明显跳动。

### 4.10 Navigation

- 底部导航只承担五个一级目的地：今日、记录、AI 助手、趋势、档案；图标和文字始终同时显示。
- 五个 PNG 图标均使用 `38 × 38px` 盒子和 `object-fit: contain`，不得再为单个导航项设置尺寸特例。
- 导航文字统一为 `12px / 700 / 15px`，图文间距 `3px`，保持单行居中。
- 选中态只改变颜色、透明度、滤镜或轻阴影，不缩放、不位移，避免切换时视觉跳动。
- 当前所有宽度均使用底部导航；桌面端限制最大宽度并居中，内容区需要为固定导航预留空间。
- 全局高频“记录”悬浮操作当前仅在今日页显示，不属于五项导航。
- 设置不是一级导航目的地时，从身份入口进入；进入设置后提供明确返回路径。
- 页面内部的 SegmentedControl 不替代一级导航，一级导航也不承担数据筛选。
- 固定导航必须避开安全区，并确保最后一项内容能够滚动到导航上方而不被遮挡。

## 5. 表单与状态

所有可编辑功能应考虑：

- 默认、悬停、按下、聚焦、选中和禁用。
- 加载、空状态、错误、成功和离线。
- 必填、格式错误、范围错误和业务冲突。
- 权限不足时隐藏管理入口；直接访问接口仍由服务端拒绝。

日期与时间使用自研选择器：

- 日期按钮保留 44px 触控目标；极小屏可压缩视觉高度但不能影响可操作性。
- 今天、选中、禁用和范围外日期必须清晰区分。
- 时间按 24 小时制显示为 `HH:MM`。

## 6. 疫苗界面规范

- 预约日期优先显示；有系统建议时可在次级文案中同时说明。
- 今日、未来 7 天和逾期状态使用文字，不只靠颜色。
- “已预约”“待预约”“逾期 N 天”“已接种”术语保持一致。
- 免疫规划和自费疫苗使用类型标签，但不把类型颜色当作唯一信息。
- 安全提示固定说明“具体接种与补种安排请以接种门诊为准”。
- 已设置门诊预约的项目在操作菜单中显示“添加到手机日历”；浏览器端使用“下载日历日程”。

## 7. 消息推送界面规范

- 明确通道为 PushPlus 微信，不写“浏览器推送”。
- 顶部显示未配置、已关闭或已开启。
- 总开关与早报、喂奶间隔、用药照护子开关分层展示。
- 喂奶一级阈值至少 30 分钟，二级必须大于一级。
- 每种推送提供独立测试按钮，结果在设置卡片内反馈。
- PushPlus 消息使用系统字体、HTML 卡片、可读标题和状态标签。
- Android 的“APP 通知”与 PushPlus 分开展示，提供总开关及早报、喂奶、照护、疫苗分类开关；每类测试按钮仅超级管理员可见。

## 8. 头像与图片

- 首页头像：76 × 76px；≤400px 时 64 × 64px。
- 档案头像按布局使用 48–56px。
- 裁剪输出：512 × 512px WebP。
- 裁剪支持单指拖动和双指缩放，手势期间禁止页面滚动；底部操作与说明必须避开安全区且不能被图片或按钮遮挡。
- 缩放范围和初始位置应确保裁剪区域始终被图片覆盖；处理失败时保留原资料并给出错误。
- 无头像显示默认小熊插画。
- 存储路径：`{DATA_DIR}/uploads/avatars/avatar_{uuid}.webp`；访问路径：`/avatars/{filename}`。

## 9. 响应式与无障碍

主要断点：

- 320–520px：单列，底部导航，卡片内边距 12–16px。
- 521–759px：单列或局部紧凑双列。
- 760–1079px：主要内容可双列。
- ≥1080px：内容最大宽度 1080px，不无限拉伸。

通用要求：

- `:focus-visible` 焦点清晰且不被裁切。
- 图标按钮提供 `aria-label`，装饰图片使用空 `alt`。
- 弹窗设置 `role="dialog"`、`aria-modal` 和标题关联。
- 动态结果使用适当的 `role="status"` 或 `role="alert"`。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
- 核心触控操作使用至少 44 × 44px 热区；其他目标至少符合 WCAG 2.2 AA 的 24 × 24 CSS px 与间距要求。
- 键盘顺序跟随视觉顺序；不能通过正数 `tabindex` 人工重排。
- 页面放大到 200% 时不丢失内容或功能，320px 宽度下不出现页面级横向滚动。

## 10. CSS 实现与维护规范

### 10.1 当前目录与加载顺序

```text
src/styles/
├── foundations.css
├── base.css
├── layout.css
├── light.css
├── hero-records.css
├── dark.css
├── charts.css
├── chat.css
├── milestone.css
└── components.css
src/ui.css
```

- `foundations.css` 定义基础 token、尺寸、排版、动效和层级。
- `light.css` 与 `dark.css` 映射主题颜色和必要主题覆盖，不改变组件几何尺寸。
- `base.css`、`layout.css` 管理基础元素、应用外壳、页面结构和响应式布局。
- `ui.css` 管理日期选择器、确认框、菜单、分段控件等共享 React UI。
- `components.css` 最后加载，用于跨页面共享组件状态和迁移期收口；不得长期堆积页面特例。
- 实际加载顺序以 `src/main.tsx` 为准，当前为 `foundations → base → layout → light → hero-records → dark → charts → chat → milestone → ui → components`。

### 10.2 禁止事项

- 新增页面规则时直接写十六进制色值、`rgb()` 或 `rgba()`；插画遮罩和确实需要透明叠加的场景除外，且应有注释。
- 使用超过三层的页面后代选择器修补权重，或依靠文件末尾“最终覆盖”纠正旧规则。
- 在浅色与深色主题中定义不同的间距、圆角、字号和布局。
- 为单个页面重新实现按钮、表单、弹窗、Toast、卡片或导航。
- 使用 `!important` 解决常规优先级问题；第三方内容和无障碍强制规则需要例外说明。
- 通过缩小到 11px 以下或把点击区压缩到 24px 以下解决移动端拥挤。

### 10.3 校验与变更要求

- 每次跨页面样式修改至少运行 `npm run typecheck`、`npm run check:css` 和 `git diff --check`。
- 视觉修改需检查浅色、深色、移动端和桌面端；表单修改同时检查默认、聚焦、选中、禁用和只读状态。
- 删除旧规则前先确认无引用，并优先删除重复选择器，而不是继续提高权重。
- 新增或替换图形资源后检查原始尺寸、透明边缘、`object-fit` 和实际视觉重心。
